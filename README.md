# 二轴手势桌面机器人（ESP32 + OLED + 双舵机 + 网页手势控制）

摄像头拍到的手势，通过笔记本浏览器（Chrome）识别后，**经蓝牙**发给 ESP32：
头部舵机跟随手掌位置转动；OLED 屏根据手势切换表情。

```
┌──────────────┐   摄像头    ┌──────────────────┐   BLE    ┌────────────────────┐
│ 笔记本摄像头 │ ─────────▶ │ Chrome 网页控制台 │ ───────▶ │ ESP32-WROOM-32     │
│              │  MediaPipe │ (MediaPipe Hands) │  文本指令 │ 双舵机 + OLED 表情 │
└──────────────┘            └──────────────────┘          └────────────────────┘
```

## 手势与效果

| 手势 | 识别依据 | 头部动作 | OLED 表情 |
|---|---|---|---|
| 五指张开 | 四指全部伸直、拇指与食指分开 | 跟随手掌位置 | 笑脸 |
| 五指捏合 | 拇指与食指指尖相触（捏） | 跟随手掌位置 | 哭脸 |
| 握拳 | 四指全部蜷起 | 跟随手掌位置 | 委屈巴巴 |
| 手移出画面 | 连续 0.6 秒无手 | 缓慢回正 | 待机脸 |

手掌在画面中的位置映射头部朝向：手往左/右移动→头左右转，手往上/下移动→抬头/低头。
方向不对时在页面右侧勾选「左右/上下方向反转」即可，不用改固件。

## 二、接线总表

### OLED（7 脚 SPI，与你已点亮的屏幕一致）

| OLED | ESP32 |
|---|---|
| GND | GND |
| VDD | 3V3 |
| SCK | GPIO18 |
| SDA | GPIO23 |
| RES | GPIO4 |
| DC | GPIO2 |
| CS | GPIO5 |

### 舵机（信号线接 ESP32，电源走外部供电）

| 舵机 | 接线 |
|---|---|
| 舵机 1（左右 pan）信号线（橙/黄） | GPIO13 |
| 舵机 2（俯仰 tilt）信号线（橙/黄） | GPIO14 |
| 两个舵机 VCC（红） | 外部电源 **5V** |
| 两个舵机 GND（棕） | 外部电源 GND，**且该 GND 必须与 ESP32 的 GND 接在一起（共地）** |

> 关键：只共信号、不共地，舵机会乱抖或不转；外部电源和 ESP32 必须共地。
> 两个舵机的电流峰值约 1A，USB 口和 3V3 引脚都供不起。

## 三、舵机机械安装（避免装歪）

1. 先只接一个舵机、烧录固件，让它转到 90° 中位；
2. 舵机断电后把云台摇臂/舵盘装到「水平居中」位置（pan 舵机摇臂朝前，tilt 舵机头部端正）；
3. 上下舵机限位：固件里 pan 限制 30°–150°，tilt 限制 60°–120°，避免顶死支架堵转；
4. 装配顺序：pan 舵机在底座（垂直向上安装）→ 上方托架 → tilt 舵机（水平方向安装）→ 头部，OLED 装在头部正面。

## 四、烧录固件

1. Arduino IDE 库管理器安装：
   - **U8g2**（作者 oliver）
   - **ESP32Servo**（作者 Kevin Harrington）
   - BLE 库随 ESP32 开发板包自带，无需安装；
2. 打开 `firmware/gesture_robot/gesture_robot.ino`，开发板选 **ESP32 Dev Module**，上传；
3. 成功后：两个舵机转到中位，OLED 显示待机脸 + 底部 `Waiting BLE`。
4. 1.3 寸 SH1106 屏：按固件文件末尾注释替换一行构造函数。

## 五、启动网页控制台

浏览器要求：**桌面版 Chrome 或 Edge**（需要 Web Bluetooth，且摄像头要求安全上下文）。
必须通过 `localhost` 或 https 打开，直接双击 HTML 无法调用摄像头。

1. 打开命令行（Win+R 输入 `cmd`），进入 web 目录，例如：
   ```
   cd /d C:\Users\wyr\Doubao\chats\2026-10-16\new-chat\gesture-robot\web
   python -m http.server 8000
   ```
   （没有 Python 时可用 VS Code 的 Live Server 插件，或 `npx serve .`）
2. Chrome 打开 `http://localhost:8000/gesture-robot-console.html`
3. 点「打开摄像头」并允许摄像头权限；首次会从 CDN 下载手势模型（约 7MB，页面自动在
   fastly / jsdelivr / unpkg 三条线路间切换，国内网络也能加载），请耐心等待提示
   「请把手放入画面」；若三条线路均失败，需开启系统代理后重试；
4. 点「连接机器人」，在弹出的设备列表里选择 **GestureRobot**，配对连接；
5. 底部状态变绿「已连接」后，手掌进入画面即可控制；OLED 表情随手势切换。

## 六、通信协议（便于二次开发）

- BLE 自定义 Service：`6e8a5d02-1a2b-4c3d-9e0f-111122223333`
- 可写 Characteristic：`6e8a5d03-1a2b-4c3d-9e0f-111122223333`
- 网页每 60ms 发送一条 ASCII 指令：`P090T090E1\n`
  - `P`：左右舵机角度，30–150，中位 90
  - `T`：俯仰舵机角度，60–120，中位 90
  - `E`：表情 0=待机 1=笑脸 2=哭脸 3=委屈
- 断开蓝牙或 1.5 秒无指令，固件自动回正并显示待机脸。

## 七、常见问题

| 现象 | 排查 |
|---|---|
| 连接列表里找不到 GestureRobot | 确认固件已烧录、板子通电；看串口监视器是否打印 `GestureRobot BLE ready`；关掉手机上其他可能占用 BLE 的连接 |
| 网页连不上/提示没有蓝牙 | 笔记本要有蓝牙且 Win10/11 蓝牙开关已开；Chrome 需用 localhost 打开；台式机可加 USB 蓝牙适配器 |
| 摄像头打不开 | 必须 localhost 或 https；检查系统摄像头权限、是否被其他软件占用 |
| 舵机不转/剧烈抖动 | 多半是供电：必须外部 5V 且共地；电池电量不足时也会抖 |
| 头转的方向反了 | 页面勾选「左右方向反转」「上下方向反转」 |
| 头动但表情不变 | 检查手势识别状态文字，捏合时拇指尖与食指尖要真正接触；光线不足时识别率下降 |
| 手势识别很卡 | 网页代码里把 `modelComplexity: 1` 改成 `0`（轻量模型，帧率更高） |
| 表情画面偏移/错位 | 1.3 寸 SH1106 换构造函数（见固件末尾注释） |
| 舵机有持续嗡嗡声 | 机械限位太紧，或角度超出支架行程，收紧固件里的角度范围 |
